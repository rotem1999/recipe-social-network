# QA review: CookBook, 2026-09-29

Branch `Dev`, commit `d6db51e`, SPEC.md Draft 5 (2026-09-29). API `http://localhost:3000/api/v1`, renderer `http://localhost:4200` in Chromium (Playwright 1.63 headless at 1280x860 and 390x844). The Electron shell was not run. Screenshots live in `docs/reviews/screenshots/`.

---

## 1. Verdict

The headline social feature is broken: Discover skips the first page of public recipes, so with fewer than nine public recipes in a category nobody ever sees a single one, and editing a public recipe makes it vanish from Discover. The session handling is careless: stop the backend for a minute and the app throws the user's session away, lose a token and the app keeps pretending you are signed in while every screen prints "Missing bearer token". The AI features cost real money on every Home visit, show one pick out of a ranked list, and hand the family half-finished sentences because the token budget is too small for the model. Visually it follows the Organic guide faithfully and does not look like a purple-gradient template, but the parts the guide did not draw (editor, nutrition box, error states, narrow windows) were plainly never looked at by a person cooking dinner: 1595 kcal per portion of teriyaki chicken, "Shared with 0 friends" shown to the friend it was shared with, and "1 servings".

## 3. Setup problems

1. **Pending migration is invisible (recorded by the launcher, not reproduced here).** When the dev servers were first started after pulling SPEC Draft 5, migration `1759100000000-SaveOwnership` had not been applied. The entity's `forked_at`, `synced_version_number` and `external_title` columns were missing and every recipe query returned 500 (`QueryFailedError: column RecipeEntity.forked_at does not exist`, still visible in the API log from 19:57). Nothing in README.md or in the API startup warns that a migration is pending. `pnpm nx run api-data-access-db:migrate` (README step 4) fixed it. See QOL-013.
2. **The raw TypeORM CLI cannot be used for diagnosis (recorded by the launcher).** `typeorm-ts-node-commonjs migration:show -d libs/api/data-access-db/src/data-source.ts` fails with "missing database environment variable(s)" because only the Nx task loads the env file. `libs/api/data-access-db/project.json` has only `migrate` and `migrate:revert`; there is no `migrate:show` target.
3. **Firebase is configured but unusable.** Every image upload returns 500. The API log shows the Google Cloud Storage call to `https://storage.googleapis.com/upload/storage/v1/b/default/o?...` failing with 403 `accountDisabled`: "The billing account for the owning project is disabled in state closed". Two facts in that line: the bucket name the API uses is literally `default`, and the Firebase project's billing account is closed, which contradicts IMG-1 ("Blaze plan (already active)"). This is configuration on Rotem's side plus a code gap (BUG-002).
4. **Service status found from behaviour:** OpenRouter works (paid `minimax/minimax-m3`, answers logged); TheMealDB v2 paid key works (Beef returns 95 catalogue entries, not the single test-key item); USDA FoodData Central works (matches returned, 4 to 9 s first load); Open-Meteo works (Jerusalem 19 °C cloudy); Firebase is configured but failing (item 3).
5. **API dev process runs with the Node inspector open** ("Debugger listening on ws://localhost:9229/...") and prints `DEP0205 module.register() is deprecated` on every start. Harmless in development; noted so nobody ships it.

## 5. Findings

Sorted by severity. IDs are review IDs, not SPEC IDs.

### Critical

#### BUG-001 Discover skips the first page of public recipes, so new public recipes never appear

- **Severity:** Critical
- **Type:** Bug
- **SPEC ref:** DISC-1, DISC-2, DISC-3, DISC-9, WX-10, SAVE-1 (§5, §8)
- **Where:** `GET /discover`, `POST /recommend` (scope `discover`); `libs/api/feature-recipes/src/lib/recipe-dto.service.ts:146` (`skip: Math.max(page, 0) * pageSize` with a 1-based `page`), called from `libs/api/feature-discover/src/lib/discover.service.ts` (page 1, page size 20 filtered / 8 overview) and `libs/api/feature-recommend/src/lib/recommend.service.ts` (page 1, page size 30).
- **Steps to reproduce:**
  1. As user A, create a recipe in category Vegetarian and set it Public.
  2. As user B, open Discover. Look at the Vegetarian section.
  3. Click the Vegetarian chip (filtered view).
  4. Create 8 more public Vegetarian recipes (any user) and repeat step 2.
- **Expected:** DISC-9: "returns, for that category, the public user recipes (newest version, newest first, 20 per page …)"; the split view shows each category's "first 8 items". WX-10: discover candidates are "the 30 newest public recipes".
- **Actual:** Step 2 and 3 show only TheMealDB tiles. The API query uses `LIMIT 9 OFFSET 8` for the overview and `LIMIT 21 OFFSET 20` for page 1 (visible in the API error log). With 10 public Vegetarian recipes the split view shows only the 2 oldest and the filtered view shows none. Editing a public recipe bumps its `updated_at`, which moves it into the hidden range, so every edit makes a recipe disappear. The Discover recommendation gets `skip 30`, has no candidates until 31 public recipes exist, and always shows "No recommendation right now". Because there is no search, a public recipe cannot be reached at all in the UI unless it happens to be old enough.
- **Screenshot:** `screenshots/BUG-001-split-view-shows-only-oldest.png`, `screenshots/BUG-001-filtered-view-no-public-recipes.png`
- **Suggested fix:** Compute `skip` as `(page - 1) * pageSize` (with `page >= 1` already enforced by validation). Add an API e2e test: one public recipe must appear on page 1 of its category, in the overview and as a discover recommendation candidate.
- **Confidence:** Verified

## 6. "AI smell" hall of shame

1. **The nutrition box.** A giant Caprasimo "4" or "1595" over "kcal per portion · USDA FoodData Central", a pretty segmented switch, and an 11 px grey confession that it is all partial. Looks authoritative, means nothing. Nobody who cooked this soup ever looked at that number.
2. **"Shared with 0 friends", shown to the friend.** Written from the owner's DTO, never opened in the recipient's account.
3. **The recommendation card.** Sage, round, a fork-and-knife medallion, "FROM YOUR SAVED RECIPES" kicker, then one pick out of three, fourteen seconds of "Reading the weather…", and sometimes the pick and "No recommendation right now" at once.
4. **Error handling by `error.message`.** "Missing bearer token", "Failed to fetch", "Internal server error", "ingredient 1: name is required" pasted straight into a family cooking app, next to "0 recipes" and "No friends yet".
5. **Discover that never shows a user's recipe.** A social network whose feed is 100% TheMealDB stock photos; every card's category tag repeats the section heading it sits under.
6. **The Nx default favicon.** The scaffold was never replaced.
7. **Pill everything.** A multi-line description box shaped like a capsule, a Visibility `<select>` shaped like a capsule, a two-line "New recipe" capsule at narrow width. Mandated by the guide (UI-6), but applied without looking.
8. **"1 servings", "3 cup brown rice", "0.75 cup soy sauce".** The formatter was tested, the output was not read.

## 7. Questions for Rotem

1. **PERF-001** Should recommendations be cached (per user, scope and local hour, until the weather condition changes or "Show another" is pressed), so tab switches stop costing money and quota? Should a single candidate skip the model?
2. **BUG-006** What completion-token budgets (or reasoning settings) should COOK-10 and WX-10 use for `minimax/minimax-m3`, and should a `length`-truncated answer be shown, retried or reported as an error?
3. **BUG-008** How should a partial nutrition total be presented ("at least N kcal", hidden, or a range)? Should volume units of dry goods use a per-food density rather than water density?
4. **BUG-011** What should every screen show when the server is unreachable or returns 5xx? (Proposed: one "Can't reach CookBook's server. Retry" message and no counts or empty states.)
5. **UX-002** What is the minimum window size: a `BrowserWindow` `minWidth`, or a responsive layout down to 390 px?
6. **QOL-001** Should the editor warn before discarding unsaved changes, and should image add/remove in edit mode wait for "Save version"?
7. **QOL-005** Should cook mode show the ingredient list, support arrow keys and Enter, play a sound when a timer ends, and keep timers running across steps (this changes UI-15)?
8. **SPEC-004** What upper limits apply to servings, minutes, text lengths and the number of ingredients and steps?
9. **BUG-017** What should happen for time zones without a city (`Etc/UTC`, `Etc/GMT+2`), and should geocoding accept only exact name matches?
10. **QOL-008** Should the current screen and cook step survive a window reload (sessionStorage)?
11. **QOL-007** Should Sync on a fork ask for confirmation, and should the banner wording differ between saved copies and forks?
12. **QOL-002** Should publishing to Public ask for confirmation? Should choosing "Shared" wait for the friend list before saving?
13. **SPEC-002** Should the receiver of a friend request be able to cancel it (FR-4 as written), or should FR-4 say the receiver declines?
14. **FR-2 (observed, not a finding)** Sending a request to someone who already sent you one auto-accepts both; after a decline the sender can send again immediately, with no cooldown and no notice that they were declined. Is that the intended behaviour?
15. **UX-006** Should user-entered and AI text follow its own direction (`dir="auto"`), given §15 excludes UI internationalisation?
16. **UX-009** What should Home's recommendation card say to a user with no recipes, and what is the loading text while the AI works?
17. **SPEC-006** Should NUT-8 strip container words such as "cloves" and "breasts" before choosing the head word?
